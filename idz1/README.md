# Общая идея решения

- Создание, редактирование и удаление банковских счетов.
- Управление категориями (создание, редактирование, удаление).
- Создание, редактирование и удаление операций (доходы и расходы).
- Экспорт и импорт данных в форматах JSON и YAML.
- Аналитика, включающая подсчет баланса и разницы между доходами и расходами.
- Пересчет балансов для всех счетов на основе операций.

# Реализация принципов SOLID и GRASP

### SOLID
1. Single Responsibility Principle:
    - Каждый модуль отвечает за одну задачу:
    - facades — фасады для работы с бизнес-логикой.
    - handler — обработчики пользовательских действий.
    - factories — фабрики для создания доменных объектов.
    - userinteraction — взаимодействие с пользователем.

2. Open/Closed Principle:
    - Добавление новых форматов экспорта/импорта возможно без изменения существующего кода, благодаря использованию интерфейсов Exporter и Importer.

3. Liskov Substitution Principle:
    - Все реализации интерфейсов (OperationService, UserInput, Exporter) могут быть заменены на моки для тестирования.

4. Interface Segregation Principle:
    - Интерфейсы разделены на небольшие, специализированные:
    - OperationService для операций.
    - UserInput для взаимодействия с пользователем.

5. Dependency Inversion Principle:
    - Зависимости передаются через конструкторы, а не создаются внутри классов. Например, DefaultOperationHandler принимает OperationService и UserInput через конструктор.

### GRASP
1. Controller:
    - Классы в пакете handler выступают в роли контроллеров, обрабатывающих пользовательские действия.

2. Creator:
    - Фабрики в пакете factories создают доменные объекты (BankAccount, Category, Operation).

3. Low Coupling:
    - Использование интерфейсов снижает связанность между модулями.

4. High Cohesion:
    - Каждый модуль выполняет строго определенную задачу.


# Реализация паттернов GoF
1. Factory Method:
    - Реализован в модуле factories для создания объектов BankAccount, Category, Operation.

2. Decorator:
    - Используется в decorators.TimeCommand для измерения времени выполнения команд.

3. Facade:
    - Модуль facades предоставляет упрощенный интерфейс для работы с бизнес-логикой.

4. Strategy:
    - Реализован в exporter и importer для поддержки различных форматов данных (JSON, YAML).

5. Command:
    - Используется в commands для выполнения операций экспорта и импорта.

# Инструкция по запуску

1. Склонируйте репозиторий:

    ```
    git clone https://github.com/AFK068/bot.git
    ```

2. Установите зависимости:
    
    ```
    go mod tidy
    ```

3. Запустите приложение:

    ```
    go run ./cmd/run
    ```
